## 实测速度：分场景报告

时间为 Mac 发命令至对应帧完成回执，含排队、存储、排版和面板驱动等待；没有肉眼测量像素完全稳定的时间。

| 场景 | 结果 |
| --- | --- |
| 英文教程首次在本会话打开 | 4.96 秒；此前系统已加载过部分字体，不能视为上电后的严格冷开 |
| 英文向前 8 页 / 回翻 8 页 | 中位数 1.96 / 1.87 秒 |
| 中文正文找图的连续 14 页 | 中位数 1.93 秒；范围 1.69–2.90 秒 |
| 中文跨章 8 次向前 / 8 次回翻 | 中位数 2.75 / 2.75 秒；跨章路径明显慢于同章缓存 |
| 强制字体重校验、取消后重试 | 9.07 秒；约 1.63 秒采样到首个进度反馈；该测试书随后热开 2.04 秒 |
| 正常重启后恢复中文插图位置 | 11.70 秒；冷开延迟仍需优化，不能宣称全部开书已达到两秒 |
| 点击下一页 / 上一页 / 工具 | 1.66 / 2.27 / 2.89 秒（一次有界点击样本） |

本轮没有在同一时刻同一本书重装旧版做严格速度 A/B，不能据此给出“历史 25 秒降低百分之多少”的结论。

### 相邻页字形预备 ABBA

同一本中文书、同一位置，off/on/on/off，各模式 6 次向前样本：

- 关闭：中位 2.0566 秒，564 次字形读取。
- 开启：中位 2.0653 秒，508 次字形读取。
- 结论：本样本减少了部分字形读取，但没有可见的时延收益；恢复原来的关闭设置，不据小样本强推默认开启。见 `lookahead.jsonl`。

## 测试过程中发现的限制与修正

1. 大图被预算保护挡住：有明确占位/错误，后续文字仍能继续；需要单独做有界缩放解码方案，不能直接去掉预算上限。
2. 蓝牙：首次两次模式回复超时，后来 Mac 自动接上；正常重启后复测确认模式三 ACK 和 Mac 连接成功，但设备状态仍未知。这个不一致仍未修复，模式二扫描也没有验收通过。
3. 测试脚本首次重启流程在 hardware board_ready 后过早读取 PAPER revision，出现 KeyError；等待应用页面就绪后复验成功。已修正本轮测试脚本的等待条件，原始失败日志保留。
4. 首次蓝牙测试在进入 finally 前的断言退出，遗漏即时恢复输出；发现后显式断开并恢复内置扬声器，再修正脚本让整个测试被 finally 包住。最终状态已核验，失败过程保留。
5. 五分钟采样内部空闲堆最低 19,511 B，PSRAM 最低 5,632,352 B；内部堆首末 20,343→20,439 B。期间已初始化 Wi-Fi/音频，不能用未初始化时的空闲值直接推断泄漏；余量仍需在后续并发测试关注。
6. 页眉“第19章”使用 EPUB 内部书脊编号，前言等也参与计数，与目录中的正式章号可能不同。这是已识别的 UI 表述问题；本轮未改显示逻辑。
