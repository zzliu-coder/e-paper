# 纸间：开发与维护

## 入口与界面规则

首页 → 系统设置 → 开发与维护。

维护功能属于 PAPER / GLYPH 3 系统界面。正常页复用 `paper::ui::Painter`；
存储卡缺失或被电脑占用时，应急页使用 LVGL 和 Flash 内的 MiSans 中文子集，
共用 `paper/generated/ui_tokens.hpp` 的页边距、按钮高度、圆角等参数。
应急页不能依赖 SD 字体，否则恰好在需要修复字体时失效。
系统操作说明使用中文；USB、文件名、版本号和诊断协议字段保留技术标识。
不要另建一套维护主题。修改样式应从 `design-tokens/effective-tokens.json` 开始。

## 字体在哪里

- 日常中文 UI 与阅读：SD 的 `/paper/fonts/`，MiSans 按实际字号生成 PGF 字形资源。
- 系统 UI 优先读取 `misans-ui-*` 小字库；书名缺字时读取同字号、同字重的完整字库。
- 阅读用完整 `misans-*` 字库。保留 16–40 px、400/500/700 三种字重，避免已存在的字号选择出现缺资源。
- 应急中文：Flash 只嵌入维护/待机所需的少量字形，18/22/32 px。
- 旧 `font_data` 分区本轮不擦除、不改分区表。它仍占用预留空间，不能当作已释放容量。

字号收拢的建议尚未作为默认策略应用：系统 18/22/26/32；阅读 20/22/24/26/28/32/36。
先保留现有设置与测试结果，再调整选择界面；资源文件数量不等于常驻内存占用。

## SD 安全交接

1. 设备点「USB 磁盘 / 安全交接」。阅读器关闭文件、清除字形缓存，资源锁阻止其他 SD 使用。
2. Mac 出现磁盘后，导入字体、书籍或更新包。
3. Mac 安全弹出该磁盘；设备自动接回 SD、重载字体/设置、恢复 USB 调试。

一个 USB 接口在磁盘与串口调试之间切换，磁盘模式期间调试串口会消失。
请勿在电脑仍写盘时直接拔线。设备不自动格式化任何卡。
页面内的资源检查校验 75 份界面字库、75 份完整阅读字库的头/规格/长度和拼音候选查询；
完整阅读字库内容在实际加载时仍有 SHA256、CRC 和索引校验。
电脑命令 `maintenance-deep-resources` 另可完整扫描阅读字库，耗时明显更长。
两种检查均报告当前字号与进度；设置了循环时间预算（常规 120 秒、深检 900 秒），
单个文件的读取仍依赖底层 I/O 超时。检查期间界面操作会排队，USB 状态查询可用。
请检查完成后再运行页面导航验收，避免排队超时。

## 电脑端接口

在项目目录运行 `/usr/bin/python3 host/service.py serve --port <实时端口>`，保持单一串口拥有者。
其他终端使用 `host/service.py call paper.status`、`paper.maintenance` 查询。
`paper.command` 的 `action` 可用 `maintenance`、`maintenance-resources`、
`maintenance-awake`、`maintenance-check`、`maintenance-install`、`maintenance-reboot`。
`paper.file` 提供受限目录列表和文件 SHA256；`paper.transfer` 用于带校验的分块传输。
日志与按钮调用相同维护服务。并发使用会返回忙碌，不静默重试写入。

## 资源生成与安装

使用本机已有 Python 字体环境，执行 `host/build_paper_resources.py --help` 查看参数。
工具位于 `tools/paper/`；使用真实 MiSans VF 和 Rime 简体拼音词库，拒绝测试占位字形。
`host/build_rescue_fonts.py <MiSansVF.ttf>` 生成小型中文应急字体。
`host/provision_paper_sd.py <资源目录> <实际挂载卷> --receipt <回执路径>`
仅安装清单内字体/词库，逐文件核验；同名旧资源保留在卡内 `.paper/resource-backups/`。
用户书籍不删除。请勿把电脑测试目录整体覆盖到设备。

## 固件更新与恢复

复用本机 ESP-IDF 5.5.4 与对应 Python 环境。修改版本号后执行 `idf.py reconfigure build`，
从最终应用镜像描述符核验版本；不能只看源码中的版本字符串。
不要直接照抄构建输出的 `idf.py flash` / `@flash_args`：其中还包含启动程序、
分区表、模型和旧字体分区。本产品日常更新限定为经过验证的应用镜像。

`host/paper_dev.py package <app.bin> --out <新目录>` 生成 `update.bin` 和 `update.json`，
放入 SD `/paper/updates/`。不能传整片合并固件。
设备先检查机型、芯片、项目、版本、分区布局、大小与 SHA256。
安装前重新校验，写入当前未运行的 5 MiB 应用分区，完整读回核验后才改变启动选择。
安装完成后另点「重启设备」。保持供电，避免更新期间拔卡。

本地开发包通过 SHA256 检查完整性，尚未提供发布者签名认证；只安装自己信任的构建。
安全启动或 Flash 加密开启时更新入口锁定，不修改 eFuse，不绕过保护。
两个应用分区分别从 `0x80000`、`0x580000` 开始；更新会修改启动选择 `0xd000–0xefff`。
ROM 下载恢复通道与整片原厂备份继续保留。安全弹出 SD 不等于恢复演练通过。
自动启动失败回滚、完整恢复演练必须有独立实测证据，不能从编译配置推定成功。

## 验收边界

电脑渲染、固件写回、设备运行、肉眼字体清晰度分别记录。
本轮硬件清晰度和触摸便利性最终由实机观察确认；不把命令返回成功当作物理效果通过。
本轮维护改动不代表无线网络、蓝牙、录音应用已全部完成。
