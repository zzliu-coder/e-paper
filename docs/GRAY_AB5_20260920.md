# 灰阶固定RAM平面验证：物理 FAIL

用户最终反馈“现在白屏”。关闭RAM自动交换未解决显示故障，不能认定为根因或修复成功。已停止灰阶实机尝试，发送黑白恢复命令；设备在同一boot完成恢复回执，恢复后的实际观感尚待确认。

grayab4物理FAIL后，仅改变板级状态隔离，不再改字体和波形。

## 已核实与推测

- 官方Metalio初始化R37十字节为`00 00 00 00 00 40 00 00 00 00`。
- FreeInk SSD1677初始化没有此写入；当前移植没有清除此板级遗留状态。
- [SSD1677 rev1手册](https://files.waveshare.com/upload/2/2a/SSD1677_1.0.pdf)第32页：R37 F[6]控制Display Mode2的RAM ping-pong。CC灰阶使用Mode2。
- 推测：自动交换与显式0x24/0x26灰阶平面冲突，导致相同目标帧重复显示不同。必须由实机四色、重复进入和恢复验证，不能直接宣布根因确定。

## 改动

进入每次灰阶基准前将R37十字节置零，固定RAM身份；原有板级C4基准、FreeInk灰阶LUT、CC与83完全保持。返回正常黑白后恢复官方R37参数，包括F[6]=1。只写易失显示寄存器，不烧OTP、eFuse，不改面板电压。

增加原生总线测试：模拟默认ping-pong开启，要求第一次RAM写入及激活前已经关闭；覆盖全部BUSY失败与SPI失败停止写入。先做四色块单帧，用户确认后才做文字对照与重复进出。

## 白屏后只读复核

- 恢复后再次查询：boot仍为`31ea18a886cd6d27`，mode=mono，dropped=0，恢复全刷回执成功。没有再发送灰阶、重启或刷写。
- 复核`inkdesk_bridge.cc`、`display_adapter.inc`与LVGL flush：灰阶提交使用原始2bit帧；LVGL中的1bit预览用于黑白回退，灰阶调用期间持有显示锁。仅凭这段代码不能认定1bit预览或并发覆盖是根因。
- 复核板级SPI配置与同步参数传输，未发现可据此认定白屏根因的DC配置差异。软件目标CRC、SPI成功、BUSY结束均不能证明面板接受了正确灰阶。
- 后续定位应拆开“官方黑白基准帧”“两路RAM写入”“灰阶波形激活”三个阶段，先验证目标帧/平面内容与实际总线序列，再做单次受控物理观察。仍需匹配本型号的灰阶波形依据；不继续随机调整电压或重复完整试刷。
- 当前安装版本实验按钮仍存在，正式阅读仍黑白；尚未部署禁用按钮的新固件，不能宣称灰阶入口已关闭。
