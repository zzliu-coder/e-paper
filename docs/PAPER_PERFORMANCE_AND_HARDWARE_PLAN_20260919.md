# PAPER：流畅度、刷新与官方硬件接入实施计划

日期：2026-09-19。状态：**流畅度核心与无线设置已实施并进入真机验收；后续硬件服务仍有未完成项。** 以下是原始计划与基线，实际交付范围和测试结果见 [执行记录](PAPER_PERFORMANCE_RESULTS_20260919.md)，不能把计划中的验收条目当作已通过。

## 1. 结论与实施顺序

建议沿用当前 PAPER / GLYPH 3 界面和 Metalio 官方驱动，先修正读字体、翻页、刷新之间的执行关系，再把官方已有的硬件能力接入中文设置与公共服务。

优先完成三个可独立验收的版本：

1. **流畅度版**：字体不反复加载；翻页不重复做无关工作；普通黑白页面采用快速刷新；屏幕等待不占住触摸线程；保留阅读位置的可靠保存。
2. **设置可用版**：统一功能状态；接通无线网络选择与连接；USB 磁盘、开发维护、电池、时间和电源设置走同一套后端。
3. **硬件服务版**：接通蓝牙音频控制、本地录音与播放、传感器状态，让后续录音笔、笔记等功能调用公共接口。

当前能够直接复用的官方驱动很多。最需要补的是驱动上面的任务调度、资源互斥、状态回传和中文页面。把官方整套应用启动流程一起接进来，会同时启动另一套界面、网络和云端业务，因此本计划按模块接入。

### 1.1 这次核查覆盖了什么

- PAPER 的构建入口、页面动作、输入队列、字体加载与绘制、书籍解析与排版、阅读位置保存、设置能力检查。
- PAPER → LVGL → SSD1677 的刷新调用链，以及官方已有的快速刷新路径。
- 官方板级初始化、Wi-Fi 管理、蓝牙串口协议、音频接口、电源策略、电池、RTC、加速度计、SD 与维护入口。
- 现有设备验收日志、同批生产字体文件头，以及当前设备的只读状态。没有启动录音、联网、配对或物理测试。

阅读范围是上述关键链路和相关实现，未把整个官方仓库的所有应用视为已审查。

## 2. 当前慢在哪里：事实、推测与待测项

### 2.1 当前执行链

```text
触摸/按键 → 输入队列 → Runtime 执行动作
                         ├─ 字体校验、索引、逐字读取
                         ├─ 打开书/加载章节/排版
                         └─ 保存阅读位置到 SD
                      → 整页绘制到 2bpp 画布
                      → 持有 LVGL 锁：转黑白、创建界面、提交刷新、等屏幕完成
                      → 更新 presented 版本与状态
```

上述步骤串在页面工作线程上。LVGL 锁还覆盖了屏幕等待，触摸事件的处理也会受影响。USB 心跳使用另一条路径，心跳正常不能证明页面响应正常。

### 2.2 已证实的代码问题

| 编号 | 事实与代码位置 | 用户能感受到的影响 | 修复方向 |

### 2.3 字体问题的数量依据

本地同批生产资源头信息：

| 字体 | 文件大小 | 字符数 | 索引大小 |
| --- | ---: | ---: | ---: |
| MiSans 26 px / 400 完整字库 | 4,846,951 B | 29,280 | 702,720 B |
| MiSans 32 px / 500 完整字库 | 7,012,352 B | 29,280 | 702,720 B |
| MiSans 32 px / 500 UI 子集 | 131,328 B | 599 | 14,376 B |

两份完整索引合计 1,405,440 B，超过当前 1,048,576 B 预算。动态书名等文字在 UI 子集缺字时，会回到同字号完整字库；与正文字库一起工作就可能触发这种淘汰。**是否是用户这本书的主要耗时，需 face 命中/淘汰日志确认。**

缓存淘汰还会先于字形缓存命中检查发生，所以“某个字已经画过”也不能保证省掉 face 重载。

### 2.4 已有观测与不能据此下的结论

从已有 `device-acceptance-final.jsonl` 提取的“命令已排队 → 轮询首次看到新 presented 版本”耗时：设置 4.301 s、维护 3.493 s、书库 2.975 s、传输 3.291 s；重复首页约 1.4–1.5 s。每个场景样本很少，包含传输和约 0.7 s 轮询间隔，**属于历史粗观测，不能当作驱动刷新耗时或 P95**。

本次只读查询：设备 uptime 10,878,924 ms，普通堆剩余 74,831 B、PSRAM 6,811,076 B、输入队列深度 0、触摸读错误 0、协议 dropped 0。当前在设置页，阅读器关闭；单个快照不能证明没有长期泄漏，也不能证明打开电子书失败。

待测：冷启动首次开书、同章翻页、跨章翻页、字体重验证、SD 读写等待、面板 BUSY 各自的时间。后台服务每 5 秒取一次自测日志，可能争用 SD，影响大小待 A/B 测量。

当前 5 MiB 应用槽还剩约 2.34 MiB，详见安装记录。空间余量、运行内存、屏幕刷新耗时是三个不同指标，现有证据不足以把卡顿归因于 Flash 容量。

## 3. 第一阶段：可测量的基线与一致的功能状态

### 3.1 加入低开销分段计时

修改点：`inkdesk_bridge.cc`、`runtime.cpp`、`text.cpp`、`reader.cpp`、`storage.cpp`、`lv_adapter_display.cc`；扩展 `host/paper_maintenance_acceptance.py` 或单独新增性能验收工具。

每次操作分配 `request_id`，日志记录：

- `boot_id`、动作、屏幕、书内容身份的非敏感摘要、字体规格、资源世代、逻辑帧版本。
- 入队/出队、字体验证、索引加载、字形读取、章节读取/解压、排版、记录保存、绘制、GUI 锁等待、SPI 提交、BUSY 完成。
- 索引命中/淘汰、整文件验证次数、读字节数、文件打开次数、字形命中率、峰值缓存。
- `accepted / preparing / submitted / presented / persisted / failed` 分阶段状态。收到 `queued` 仅表示接受任务。
- 普通堆/PSRAM 的剩余与最大连续块、任务栈最低余量、队列高水位、丢弃/合并原因。

计时使用单调时钟；先写小型内存环形缓冲，批量导出。正常运行不逐字输出串口、不为每个采样 `fsync`，避免测量本身制造瓶颈。不记录正文、密码或录音内容。

冷态、热态分开测试：冷态为本次挂载后首次加载该字体/书籍；热态为内容与布局不变、缓存已就绪。重启和重新挂载都生成明确的世代变化。

### 3.2 先修能力和反馈的基础问题

- 复用现有 `Capability`，补足 `available/reason/current_state/pending/last_error`，避免每个页面独立猜状态。
- USB 设置与“开发与维护”调用同一服务。区分“可启用”“正在交接”“电脑占用 SD”“正在恢复”“失败”。
- 灰阶统一检查真实硬件门禁；默认样式、单书样式、字体预览应用、恢复默认、启动读回均经过同一验证。失败保留旧有效样式。
- 不可用设置显示具体中文原因，如“无线网络界面尚未接入”“存储卡正由电脑使用”“灰阶尚未通过实机验收”。
- 无变化动作不递增画面版本、不重绘；错误也只在需要改变可见提示时刷新。首页上再次选择首页应成为可验证的无刷屏操作。
- 物理上下键按当前页面解释；队列满返回/记录“正在处理”，不静默丢弃。调试命令与设备按钮采用相同动作语义。

验收：每个设置显示状态与执行状态一致；灰阶无旁路；无效/重复动作不会无故全刷；每个被接受的命令都有完成或失败结局。

## 4. 第二阶段：字体与电子书热路径

### 4.1 字体缓存：避免重读整本字库

修改点：`paper/text.hpp`、`text.cpp`、`font_catalog.cpp`、`storage.cpp`、资源上传提交和 USB 交接入口。

1. 建立轻量 `VerifiedFace` 记录，保存文件身份、SHA、格式验证结果、`media_epoch/resource_generation`。这份记录与大索引 LRU 分离；索引被淘汰不等于验证结果被遗忘。
2. 首次完整验证尽量合并 SHA、索引 CRC、字形区 CRC 的顺序读取，避免整文件重复扫描。保留原有边界、长度、字符索引和 CRC 检查。
3. 同一挂载/资源世代内复用验证结果。USB 交还、卡重新挂载、字体发布/替换、校验异常必须失效相关缓存。文件大小和时间戳仅作线索，不能代替内容验证。
4. 将 UI 子集索引和阅读索引分池：起始预算 UI 256 KiB、完整字体索引约 1.5 MiB，可同时容纳两份当前 MiSans 完整索引。对活跃正文索引 pin；内存不足先停预取，再淘汰非活跃项。
5. 字形缓存保留有界 LRU，加哈希定位；减少长字符串 key 的反复拼装。键必须包含实际字体文件身份、字号、字重、字符和 UI/完整字库区别。
6. 复用少量打开的字体文件，建议上限 4；有并发时每个句柄的定位+读取由同一 owner 或锁保护。USB 交接先关句柄再卸载。
7. `Painter::label()` 将本次测量的 metrics 与字形视图交给绘制，生命周期覆盖绘制完成，避免二次读取与多次复制。不能留下指向已淘汰缓存的裸指针。
8. 只清除受设置变化影响的缓存。改阅读字号不清空全部系统 UI 字体；改行距不重新验证所有字体文件。

当前字体的笔画、阈值、字重和点阵资源保持不变。优化应先做到相同输入输出像素一致，避免把字形质量变化混入速度对比。

验收：同一本书同一规格连续翻 50 页时，稳定热态无整字库 SHA/CRC 重扫；动态书名触发完整 UI 字库时不反复淘汰正文；资源替换后一定重新验证；缺字/损坏仍有中文错误和可用维护入口。

### 4.2 阅读缓存：保留已经算好的工作

修改点：`document.cpp`、`reader.cpp`、`text.cpp`、`reader_style.cpp`、`reader_font_ui.cpp`。

- 在同一资源世代内缓存书籍内容身份、ZIP 索引、OPF/目录；按内容身份复用，书籍被替换即失效。退出阅读可以释放 SD 句柄，同时保留有界元数据缓存。
- 保留当前章节，预算允许时预取相邻一章；只预排相邻页。首次打开不分页整本书，也不预加载全部章节。
- 页缓存键包含：书 SHA、解析引擎版本、章节/UTF-8 字节位置、字体文件身份/规格、行距、页边、视口、排版版本与资源世代。
- 预取使用不可变章节/排版输入和独立结果。预取不能修改当前阅读位置、书签或写入阅读记录；用户换书/改字/卸载 SD 后旧任务必须取消。
- 保留已访问的页锚点；跨章返回优先从最近锚点重排。找不到锚点时使用有时间片与取消能力的后台定位任务，界面显示“正在定位”，不在一次按键回调内跑 20,000 页循环。
- 正文覆盖检查按“章节身份＋字体身份＋布局相关规格”复用；字体预览也可使用同样的已验证覆盖结果。
- 搜索属于长任务，进度可查询、退出可取消。不要让搜索阻塞显示/输入或串口心跳。

**兼容约束：**本轮保持 `paper-local-1` 的文本抽取规则、UTF-8 偏移定义、书身份和 `PAPERPOS1` 记录。CrossMux 适配文件当前未入构建；更换解析器需要单独做位置迁移与 EPUB 能力项目。

### 4.3 阅读位置保存：默认维持可靠性

当前每页保存都在刷新前完成。第一轮不默认改成“几页保存一次”，避免用户在突然断电后退回更早位置。

- 缓存有效记录代次和最后 payload，减少同一次挂载内重复读取两份记录；外部变更或错误时重新校验。
- 准备不可变的下一页计划，将画面准备与单一存储工作任务的可靠保存重叠；两者就绪才提交正常成功路径。存储线程不读取会继续变化的 `Reader` 对象。
- 保留临时文件、CRC、双槽和同步发布顺序；保存失败时保持旧已提交状态并提示。不能把“已入存储队列”标成“已保存”。
- 进入 USB 磁盘、切书、待机、关机和更新前等待存储屏障，失败则停止交接。
- 若测量证明同步落盘仍是主要瓶颈，可另做“先显示、稍后保存”选项；必须明确最多丢几页/几秒并单独确认体验取舍。本轮默认不改变这一语义。

验收：连续翻页、书签、跨章、修改字号后重启恢复一致；模拟短写/卡满时不覆盖最后有效记录；缓存命中不改变标点禁则、断行和现有阅读位置。

## 5. 第三阶段：少黑闪，同时让输入保持响应

### 5.1 刷新策略

复用现有 SSD1677 官方波形，不在本轮编写未知 LUT 或提高供电/驱动电压。

| 情况 | 默认策略 | 说明 |
| --- | --- | --- |
| 普通黑白翻页、菜单切换 | 全幅快速刷新 | 页面变化本身不再强制全刷 |
| 像素完全相同 | 不提交屏幕 | 先比较摘要，再必要时比较像素 |
| 初次显示、唤醒、显示状态恢复 | 清洁全刷 | 建立可靠的前后帧基线 |
| 用户手动“清除残影” | 清洁全刷 | 保留一个中文入口 |
| 多次快刷后 | 周期清洁全刷 | 起始参考现有常量 15 次，再按实机残影调整 |
| 大块黑白反转、显示模式切换 | 保守全刷或专门策略 | 记录原因，实机比较后再放宽 |
| 刷新失败/BUSY 超时 | 报错并进入恢复流程 | 不把旧帧标记成新帧成功 |

墨水屏仍需要时间驱动墨粒。目标是普通操作尽量直接换页、按策略清除残影；“任何情况下永不黑闪”不作为承诺。

`DrawPartialDirty()` 现阶段实际传全幅，第一轮保留这一稳定传输方式。真正只传变化矩形涉及窗口对齐、旧/新图面板 RAM 和波形状态，单列后续实验；先比较它相对面板 BUSY 时间能节省多少，再决定投入。

### 5.2 显示任务和输入任务解耦

修改点：`inkdesk_bridge.cc`、`LVAdapterDisplay`、`esp_lcd_panel_ssd1677.c`，同时照顾 selftest、应急维护、待机与唤醒路径。

1. 复用一个正常 PAPER 屏幕对象和固定数量的图像缓冲；黑白转换放在 LVGL 锁外。应急中文维护页单独保留，不依赖 SD 字体。
2. GUI 锁只覆盖对象更新和必要的 LVGL 渲染收集。准备好的不可变帧交给唯一显示 owner，释放 GUI 锁后等待 BUSY。
3. 统一显示仲裁：PAPER、selftest、应急页、待机都申请同一个 owner；任何时刻最多一个物理刷新在途。常规 LVGL flush 不再绕过 owner 私自驱动面板。
4. 帧区分 `prepared / submitted / completed`；完成消息携带帧序号。只有确认面板完成后更新 `presented` 和可交互区域。
5. 当前纸面还是旧页时，触摸按旧页版本解释；旧帧事件不能误点新页按钮。可安全合并的连续翻页按计数/目标处理；固件更新、格式相关动作等不得自动合并或重放。
6. 快刷前清理陈旧完成信号，建立本次 BUSY 周期，超时后隔离迟到中断。当前 `FullScreenPartialTo()` 未像普通路径一样显式排空旧信号，需统一处理。
7. 仅从 SPI 返回或二值信号量被唤醒不足以证明本帧完成：要结合在途状态、刷新开始和 BUSY 状态。恢复中拒绝新物理提交，不能让旧中断完成新任务。
8. 失败时保留最后可信帧；必要时重新建立面板基线。生命周期停机须等在途缓冲释放，不能重用仍在 DMA/刷新路径中的内存。

### 5.3 输入反馈

- 记录原始按下、稳定按下、接受动作、物理显示完成的时间，区分“手指按住直到松开”的交互时间。
- 可接受的操作尽早给现有短震反馈；震动不代表业务已经成功。不新增墨水屏旋转动画制造连续刷新。
- `paper.status` 始终能返回任务状态；字体校验、搜索、Wi-Fi 扫描、蓝牙连接都可见进度/失败原因。
- 限制待处理动作量，明确丢弃与合并规则；真实触摸事件继续保留原始日志以便追踪。

验收：刷新期间连续点击不导致串页误操作；50 次翻页、100 次导航无未解释丢失；全刷原因可追踪；首帧/周期清屏/异常恢复以外的普通黑白页面切换不再强制全刷。最后用短视频确认黑闪和残影，日志只证明驱动执行，不能代替眼睛观察。

### 6.2 Wi-Fi：优先接到真正可用的设置页

复用：`components/esp-wifi-connect/wifi_station.cc`、`ssid_manager.cc`、`wifi_scan_lease` 与官方电源管理。PAPER 的 `app_main()` 启动个人 SDK，没有走官方 `Application::Start()` 的完整网络启动流程，需要明确初始化责任。

具体改动：

- 在唯一网络 owner 内管理初始化、扫描、连接、断开和省电暂停。其他模块通过请求调用，不能各自 `esp_wifi_init/stop`。
- 官方 `WifiStation::Start()` 的自动尝试已保存网络保留为可配置行为；新增明确连接用户选中 SSID 的路径，避免刚选 A 却自动连到 B。
- 扫描、连接均异步，UI 显示“扫描中 / 正在连接 / 已连接 / 密码或连接失败”。`connect` 调用返回成功仅代表请求被接受；拿到 IP 才进入联网状态。
- 共用扫描所有权。现有诊断扫描有自行初始化/清理网络的路径，必须纳入同一服务，避免消费彼此的扫描列表或停止别人的连接。
- 设置连接有截止时间、取消和可控重试。页面退出释放保网需求；后台上传等活动单独持有需求，开发 USB 唤醒不自动等于永远联网。
- 校验 SSID/密码字节长度；替换运行时错误路径的 `ESP_ERROR_CHECK` 为可返回错误；处理 NVS 打开、写入、提交失败。
- 继续使用原有 NVS `wifi` 命名空间和已有凭据，不清空。新密码先临时连接验证，成功后再保存；日志不输出密码。
- 新页面使用现有中文键盘与 PAPER 组件：网络列表 → 选中网络 → 密码 → 状态/忘记网络。设置显示实际状态，不仅显示保存的 on/off。

已用 Context7 核对 ESP-IDF 5.5.4 的非阻塞扫描、事件与连接规则，参考 [Wi-Fi API](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32s3/api-reference/network/esp_wifi.html) 和 [Wi-Fi 指南](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32s3/api-guides/wifi.html)。

验收：扫描有界、错密码不重启、取消后无迟到连接污染、新旧网络切换正确、断线可恢复、页面可继续翻页；网络密码只在用户明确选用的测试网络中使用。

### 6.3 蓝牙音频：复用协议，拆出页面耦合

复用：`main/display/screen/bluetooth_screen/bluetooth_screen.cc` 中的 AT 命令和应答解析，以及 `SimpleUart`。官方路径可见 `AT+RX / AT+TX / AT+MODE / AT+INQUIRING / AT+CONNECT` 和连接成功/超时应答。

- 抽出 `BtAudioService`，负责命令、模式、扫描结果、连接任务；官方 UI 的 LVGL 对象和静态页面状态不搬进 PAPER。
- 当前 `SimpleUart::registerCallback()` 是覆盖式单回调。改成单一解析 owner 分发给日志/诊断/连接状态，避免蓝牙页替换 SDK 接收回调。
- 官方有效模式为 1/2/3，当前设置枚举为 0/1/2。采用具名模式和显式映射；旧值来源不清时显示“待选择”，不能盲目平移数字并发送 AT。
- 发送命令与收到应答分别计状态。固定 700 ms 等待只能用于协议间隔，不能作为模式切换成功的证据。
- 建立分包/粘包、行长度限制、请求超时、取消和重连逻辑。保留现有“不支持硬件复位脚”的事实，不编造复位能力。
- 模式切换与 I2S 录放音由同一音频 owner 协调；正在录音时拒绝会中断数据源的切换并给中文原因。

验收：串口注入测试覆盖拆行、连接成功、超时、模块无回复；SDK 日志同时保留。实机配对和音频方向由一轮实体设备测试确认。该模块的蓝牙音频能力不直接代表通用 BLE 应用接口已经可用。

### 6.4 音频：从已有短诊断接成可复用的录音能力

复用：`BTAudioCodec`、`AudioCodec::InputDataChecked/OutputDataChecked`；`personal_sdk.cc:1503` 的 `RecordReplay()` 已提供 3 秒、16 kHz 单声道 WAV 录放路径。PAPER 的 `RecordingPort` 目前仍为 `DisabledRecording`。

- 实现有 session ID 的 `RecordingPort`：开始 → 录音中 → 收尾 → 完成/失败/取消；另提供播放接口。长录音使用有界 PCM 缓冲流式写 SD，不把整段存进内存。
- 保留官方 I2S 引脚、从机时钟与双通道输入安排。沿用诊断已采用的麦克风通道拆分，但在真实录音中核实通道与幅度。
- 音频采集、播放、短音、蓝牙模式共用互斥租约，避免测试任务和新录音任务同时启停同一 codec。
- 保留有限 I/O 超时；核对 I2S API 的 `timeout_ms` 单位，避免用 tick 换算值充当毫秒。超时、短读写、时钟缺失都要结束任务并释放资源。
- 录音先写独立临时文件，收尾修正 WAV 头并发布；卡满/拔卡保留可恢复信息，不覆盖旧录音。自动测试只操作专用测试文件。
- 将电源需求拆清楚：现有 `PowerNeed::LocalMic` 会保网。新增纯本地采集需求，防止录音笔为保持时钟而顺带常开 Wi-Fi；功放仅在播放时开启。
- UI 用现有中文组件显示时长、剩余空间、状态与错误，低频更新；不为音量波形持续全屏刷墨。
- 云端转写单独适配。默认不上传录音；建立网络连接不等于授权把麦克风数据发给外部服务。

验收：先自动检查 3 秒文件头/长度/采样统计，再做 10 分钟流式录音、卡慢/满和中断收尾。声音可听性与麦克风清晰度需要用户说一句、听一段，集中完成。

### 6.5 电池、时间、传感器和电源：低风险优先接入

- 通过状态采样服务定时读硬件，UI 只读缓存，避免每次绘图都阻塞 I2C。电池可 5–10 秒采样，分钟/状态变化时才更新可见内容。
- 官方电量百分比由电压插值和滤波得到，不能标成已校准的剩余容量或剩余小时数。失败显示“--/读取失败”，保留最后成功时间。
- RTC 必须带有效位；无效时提示校时，不伪造当前日期。手动时间/网络校时确认后统一写系统与 RTC，并固定时区语义。
- `Sc7a20h::Begin()` 在身份未知或配置失败时仍可能保留 handle 并返回 true，所以 `IsReady()` 仅代表有句柄。补充 `probed/configured/sample_valid`；设置失败或样本不合理时不启用自动旋转。
- 震动、CPU 空闲档、待机、关机时间、开发保持唤醒继续经官方 `PowerPolicy`，不再新增另一套定时关机逻辑。
- 不改充电电压、电流、器件保护寄存器或 eFuse。本轮电池相关工作限于读取与正确展示，沿用已存在的板级初始化。

验收：I2C 不应答时其他页面和 USB 仍可用；缺失模块返回准确状态；开发唤醒/正常待机互不覆盖；时间与电池的显示来源可以追溯到成功采样。

## 7. 运行规则与资源预算

系统继续保持“底座＋内置应用”。下面的服务分工用于统一资源所有权，不引入应用安装器、Lua 或通用插件系统。

| Owner | 负责 | 明确不能做的事 |
| --- | --- | --- |
| 页面/运行时 | 解释动作、维护页面状态、准备视图 | 在 GUI 锁内校验整文件、扫描网络或等 BUSY |
| 显示服务 | 唯一物理提交、波形选择、BUSY 完成 | 让 selftest/待机绕过仲裁写屏 |
| 存储/资源服务 | 书/字库读取、可靠保存、缓存世代、USB 交接 | 电脑占卡时继续访问 FAT |
| 网络服务 | 扫描、连接、状态、网络租约 | 与诊断扫描分别初始化/停止 Wi-Fi |
| 音频/蓝牙服务 | codec、功放、模式与会话 | 多任务同时改音频路由 |
| 状态采样服务 | 电池/RTC/传感器快照 | 每个页面各自高频轮询同一器件 |

这些 owner 不要求各建一个大栈线程。采用现有任务和有限工作队列，先测栈/内部堆，再决定任务拆分。

### 7.1 内存预算

- 初始字体索引目标：UI 256 KiB＋阅读约 1.5 MiB；字形缓存先维持 256 KiB。
- 最多两个章节，每章沿用 768 KiB 上限；超预算停预取。ZIP 压缩输入、解压输出、抽取文本可能同时存在，必须记录峰值，不能只加最终章节大小。
- 2bpp 页面 96,000 B、1bpp 页面 48,000 B；明确缓冲池数量，统计 Runtime、LVGL 和显示服务已有副本，避免只计算新增缓冲。
- 字体/章节/页面的可回收缓存初始总上限建议 4 MiB，受实时余量约束；以至少保留约 2 MiB PSRAM 给瞬态工作为起点，必要时降低预取。此为待测预算，不是已验证容量结论。
- 大缓冲显式放 PSRAM，I/O/DMA/任务关键内存按平台要求分配。内部堆当前仅约 73 KiB，不能盲目加多个大栈或把缓存放普通堆。
- 每个场景记录内部最小余量和最大连续块。先拟定内部自由堆不低于 48 KiB 的警戒线，是否适合网络/音频并发须按基线调校；触发时关闭预取或拒绝新增任务，保留诊断通道。

### 7.2 SD 与 USB

现有 SD 挂载 `max_files=12`，1-bit 总线。复用字体句柄建议最多 4，再给书、记录、录音、传输和日志留预算；所有子模块共同计数。先不增加文件上限，不假设可切 4-bit。

USB 磁盘交接顺序：停止接收新 SD 作业 → 取消预取 → 完成必要保存/录音收尾 → 关闭句柄 → 等所有租约释放 → 卸载 → 交给电脑。安全弹出后重新挂载、更新世代、重新验证必要资源，再恢复使用。

USB 磁盘与现有调试接口仍按当前硬件/固件方式分时使用；已有弹出流程可能重启，重连必须以 `boot_id` 识别新会话，不能宣称无重启。

### 7.3 后台开发服务与日志

保留现有单 owner USB 服务。日志导出增加文件长度/代次或增量通知，未变化文件退避；前台翻页、录音时减少后台 SD 读取。对“原始日志策略/退避策略”做同书同页 A/B，不先声称日志轮询是主因。

新增性能日志有大小上限，只轮转本功能自己的日志。书籍、录音、字体、用户笔记和备份不纳入自动清理。PAPER 若增加磁盘页缓存，也限定在专用可重建目录并单独设配额。

### 7.4 Flash

先记录每阶段应用 `.bin/.map` 和组件增量。复用已经链接的驱动，关闭未使用官方 UI 的入口，保留中文应急维护字库。是否裁掉官方未引用模块以链接图和回归测试决定，不能按文件名直接删除。

本计划不改分区表、旧字体分区或双应用槽，不用扩大单槽破坏回退材料。优先让本阶段新增应用体积控制在约 512 KiB 内；超过时单列来源与取舍，再决定是否接受。资源字库继续存 SD。

## 8. 验收标准：怎么证明确实变快、接入确实可用

### 8.1 自动测试

| 类别 | 测试内容 | 必须留下的证据 |
| --- | --- | --- |
| 像素与字体 | 原字号/字重/中英文/缺字补字/黑白底；预备文字绘制前后对比 | 相同页面像素哈希或已解释差异；字体身份 |
| 缓存 | 两份完整字体交替；UI 动态书名；同字号字库被替换；坏 CRC | 命中/淘汰/校验次数、错误码、世代变化 |
| 阅读 | 冷开/热开；同章 50 页；跨章 10 次；倒翻；目录跳转；改字号 | 位置、页内容、各阶段时长及恢复记录 |
| 可靠保存 | 卡满、短写、损坏一份记录、保存中退出/USB | 最后有效记录保留；无误报保存成功 |
| 显示/输入 | 100 次导航；刷新中点击；陈旧完成信号；迟到中断；BUSY 超时 | 帧序号与输入对应、刷新原因、恢复结果 |
| 网络 | 扫描冲突、错密码、取消、断线、省电恢复、NVS 写失败 | 任务状态；IP 事件；无凭据日志 |
| 蓝牙/音频 | UART 分包/超时；录音与模式切换冲突；短读写；卡慢/满 | 状态机测试、PCM/WAV 指标、资源释放 |
| 生命周期 | 无 SD、重新挂载、USB 安全弹出、重启/待机/唤醒 | 设备/会话身份、挂载世代、故障后诊断可用 |
| 稳定性 | 先 30 分钟自动回归，再进行长期使用/老化 | 堆与队列趋势、异常原因、失败可追踪 |

30 分钟是筛查循环累积问题的检查点；它不代表某个硬件标准，也不替代长期稳定性。根据前面的问题密度决定是否追加更长老化。

### 8.2 性能目标与测量规则

先采每个固定场景至少 30 次热态样本，冷态独立记录；输出中位数、P95、最大值。使用同一本书、同一字号、同一资源、同一刷新策略，同时记录温度/供电等可取得条件。

以下为工程目标，尚未实测达成：

- 原始稳定按下到动作接受/轻反馈：P95 目标 ≤100 ms；LVGL 点击动作另记松开时间。
- 热态普通页面和同章翻页的非面板准备时间：P95 先争取 ≤200 ms；持久化慢写另外报告，不能隐藏在平均值里。
- 页面总时间分开报告 CPU/SD/等待/面板。最终判断以总时间下降和物理效果通过为准，不能只优化心跳或 `queued` 返回速度。
- 成功热态翻页没有整字体文件重扫、没有整本书重新算 SHA、没有全章反复验证；同页无变化不提交屏幕。
- 普通黑白导航/翻页采用快刷；全刷只来自明确策略，能从日志逐次解释。
- 初次完整字体验证耗时先实测再设目标，提供进度；不能用取消校验来制造“瞬开”。

若目标达不到，报告具体卡在字体、SD、排版、锁或面板的哪一段，再做下一项优化。

### 8.3 用户只需集中做的一轮检查

自动测试通过、设备停在可测试页面后，再请用户：

1. 用一段连续操作确认：首页 → 设置 → 书库 → 阅读 → 连翻/倒翻，观察反应、黑闪、残影和字形。
2. 按一次底部三键和侧键/AI 键；必要时轻晃设备，确认输入/震动/方向。
3. 如需要新网络，选择测试网络并输入密码；如接蓝牙，配对一次测试设备。
4. 说一句话、正常桌面距离听回放。

电脑自动关联 request ID、设备版本和日志。完整原厂恢复演练单独安排，不能把这轮 UI/音频验收视为恢复通过。

## 9. 实施与交付检查点

| 顺序 | 范围 | 阶段结束条件 |
| --- | --- | --- |

交付物包括：

- 新源码及版本指纹；不覆盖现有未提交成果。
- 自动性能报告：基线与改后各阶段时间、缓存/I/O/内存、刷新模式次数。
- 中文设置和公共服务接口说明；支持范围分 `已接线 / 自动验证 / 物理验证`。
- 固件、SHA、实际写入清单与读回记录；依赖与资源清单。
- 回归测试、可重复场景与维护/恢复说明。

## 10. 刷写和恢复边界

执行阶段沿用已验证的维护更新服务。用户已给常规写入授权，仍在实际写入前列出本次文件、SHA、目标槽与地址、扇区范围、启动选择变化和回退路径；运行槽可能变化，地址必须现场读取。

- 正常更新只写核对后的应用槽及必要启动选择；禁止修改 eFuse、绕过保护、盲用默认刷机参数。
- 保留当前 maint3 镜像、原厂完整备份和旧槽/启动区证据；不格式化 SD，不改用户书籍/字体选择/笔记。
- 字体/缓存格式本轮优先保持兼容，使应用回退不依赖重装几百 MB 资源。
- 写入后分别核验镜像读回、启动身份、调试通道、字体资源、页面与阅读场景。构建成功不能代替上述验收。
- 双槽更新已经有成功记录；自动启动失败回滚、整片原厂恢复仍按原记录标记 `NOT_PROVEN`，不在计划中提前宣称完成。
