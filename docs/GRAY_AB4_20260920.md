# 常规字体与真灰阶 v4 对照

## 最终物理结论：FAIL（优先于下方数字回执）

用户照片显示白底大面积颗粒、旧阅读页面残留、前三块灰度未清楚分离；后续再次进入真灰阶出现整屏白屏。白屏时设备仍同一boot、dropped=0、目标CRC=3638663962且三阶段返回成功，因此数字PASS无法判断物理输出。用户确认切回黑白并清屏后暗底消失。已再次恢复黑白，不继续灰阶文字测量。

下一候选仅核查/修正R37 F[6]的RAM ping-pong设置：板级黑白初始化开启0x40，FreeInk初始化未开启，该状态被灰阶继承。SSD1677 rev1第32页明确说明它对Display Mode2自动交换RAM；固定两平面灰阶需隔离此状态。这是有源码和手册依据的待验证原因，尚非根因已证实。不尝试X4的factory LUT或随意更改VCOM。

用户实测：700太粗；笔画微调无明显收益；网点模拟更好；小字的暗区和笔画问题更明显。移除实验中的700行与stroke选项/算法，不删除SD字体，不改变系统标题层级和阅读设置。

## 本轮机制与边界

- 保留mono、dots，加入隔离的gray4实验。MiSans 400，18/22/26/32px，同一coverage母版，白底与反白逐像素互补；三模式只改变输出方式。
- 第一次进入真灰阶先显示黑、深灰、浅灰、白校准块，点换字号才能进入文字；后续切换模式保留同页。该操作不产生物理PASS，也不持久化灰阶已验证标志。
- 真灰阶每一帧使用板级官方快刷LUT与0xC4建立黑白基准，再运行FreeInk固定灰阶LUT和0xCC，最后0x83关闭模拟电源。取消本机实验中的OTP F7/FC基准和快刷复用，优先验证确定性；不乱改面板电压/波形字节。
- 黑白恢复也走板级LUT/C4；任何BUSY超时或传输失败使基准无效，禁止继续假定成功。实验保持原来的单显示锁与有界等待。
- 增加128字节内部同步发送缓冲。IDF 5.5.4自身已有DMA自动缓冲机制，因此不能把此项当作旧花屏根因已证实；主要待验假设是旧OTP基准与本机板级初始化不一致。
- PAPER_GRAY_EXPERIMENT开启；PAPER_GRAY_VERIFIED关闭，普通阅读仍黑白。

## 验收步骤

1. 电脑验证15种像素输出、四色值、常规字重、反白互补、模式切换、清屏CRC不变和默认设置。
2. 测试C4→CC→83顺序、恢复C4→83；注入每个BUSY等待失败和部分SPI失败，失败后不再写。
3. 安装后先检查版本、槽位和USB回执，验证黑白/网点路径。
4. 真机只先显示真灰阶色块，请用户确认白底干净、四色分明、没有旧画面或噪点；数字回执仅证明命令执行。
5. 色块通过后，用换字号与三模式比较字体；观察黑底白字、细笔画、刷新等待和闪烁。退出/返回原始黑白应恢复干净画面。未观察到的项目保留NOT_PROVEN。
