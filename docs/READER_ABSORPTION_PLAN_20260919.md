## 1. 结论：两项优先接入，一项条件实验

保留 PAPER 的中文界面、设计指纹、字体选择、官方硬件驱动、USB 开发维护和双应用槽恢复路径。吸收范围限定在阅读内容链路、显示状态管理及必要的字形预备。

| 候选 | 本轮决定 | 要获得的具体收益 | 接入前提 |
| --- | --- | --- | --- |
| CrossMux EPUB 内容链路 | **优先推进独立模块适配** | 真实显示 JPEG/PNG 插图；保留段落对齐、缩进、强调和标题区别；改善再次打开及跨会话缓存 | 完成解析→排版→绘制整条路径；字体与存储适配通过；普通文本不明显退步 |

**已有快刷、字形缓存、排版缓存、硬件初始化和调试通道全部复用。** 不换操作系统，不引入另一套首页，不重做第二份分页缓存。

此处“收益”包含内容能力提升与响应改善。带来插图和样式属于能力收益；速度收益须同机对照实测，不能用代码量、功能数量或编译通过替代。

### 2.2 现有性能基线

依据 [perf2 执行记录](PAPER_PERFORMANCE_RESULTS_20260919.md) 和 `artifacts/paper-perf2-20260919/device-performance.jsonl`：

- 同一会话暖翻页代表值约 **1.532 秒**，继续阅读约 **1.532 秒**。
- 冷开现有 EPUB 为 **27.614 秒**，首次显示无线扫描结果为 **9.412 秒**。
- 单独字库 SHA 操作约 **4.149 秒**，书籍 SHA 操作约 **1.125 秒**。
- 当前字体索引预算：正文 1536 KiB、界面 256 KiB；字形缓存 256 KiB；章节上限 768 KiB。
- 最近一次冒烟末尾：内部堆约 52 KiB、PSRAM 可用约 5.68 MiB；只是一次状态快照，不能当成最坏峰值或承诺预算。
- 应用镜像约 2.56 MiB，应用槽 5 MiB。剩余空间还要留给音频、笔记等功能。

这些旧样本数量有限，尚不能建立稳定的 P95。实施第一个步骤应复测标准场景，不能拿单次最快值作比较。

## 3. 已证实的差异：做什么、跳过什么

### 3.1 EPUB 当前受限在“页面模型”

当前 [Chapter / DocumentSource](../components/paper_core/include/paper/document.hpp) 以 `text + anchors + links` 表示章节；[markupToChapter](../components/paper_core/src/document.cpp) 跳过 `style`，图片转换为文字占位；[Reader::paint](../components/paper_core/src/reader.cpp) 只按文本行绘字。因此光换解压器或章节读取器无法显示原书插图。

[CrossMuxSource](../main/paper_shell/adapters/crossmux_source.cc) 目前只接容器/元数据和资源读取，`chapter()` 最后仍调用 `markupToChapter()`。该文件没有列入当前 [product_sources.cmake](../main/paper_shell/product_sources.cmake)，[Runtime 构造](../components/paper_core/src/runtime.cpp) 默认实例化 `LocalDocument`。**文件存在不代表运行中的阅读器已经使用完整 CrossMux。**

上游值得保留的闭环：

- `ChapterHtmlSlimParser` 形成有样式的内容与图片块。
- `ParsedText` 计算文字度量、断行和中文标点边界。
- `Section` 持有排版结果和缓存；已有 `startBuild / buildSomeMore / loadPage / suspendBuild`，支持分段构建。
- `Page` 包含文字行、图片和横线，交给绘制器。
- `ImageBlock` 在需要访问页面时抽取/解码图片，并能复用像素缓存。

来源：[解析器](https://github.com/0x1abin/crossmux/blob/7dcd8b19031c9277376c7e0f8cacda4d7b5a43a1/lib/Epub/Epub/parsers/ChapterHtmlSlimParser.cpp)、[排版](https://github.com/0x1abin/crossmux/blob/7dcd8b19031c9277376c7e0f8cacda4d7b5a43a1/lib/Epub/Epub/ParsedText.cpp)、[Section 接口](https://github.com/0x1abin/crossmux/blob/7dcd8b19031c9277376c7e0f8cacda4d7b5a43a1/lib/Epub/Epub/Section.h)、[图片块](https://github.com/0x1abin/crossmux/blob/7dcd8b19031c9277376c7e0f8cacda4d7b5a43a1/lib/Epub/Epub/blocks/ImageBlock.cpp)。

边界也已查明：当前 `CssParser` 明确处理一组有限属性；标题路径主要通过单独块、对齐和加粗区分。不能承诺任意 CSS `font-size/font-family`、所有标题大小层级或浏览器级网页效果。`ImageDecoderFactory` 当前选择 JPEG/PNG 解码器，不能把“支持插图”扩大成任意图片格式或 OCR。

### 3.2 刷新存在增量空间，已有能力无需重复

当前 [RefreshDiagnostic](../main/display/lv_adapter_display.cc) 已具备：同图跳过、普通页快速刷新、每15次局刷后全刷、失败后 `has_last=false`、显示所有权和释放 GUI 锁等待。

进一步读到：`DrawPartialDirty()` 当前忽略 `prev_fb`，只提交新画面，依赖控制器已有 RAM 状态；主机侧 `has_last` 不足以表达“控制器两份 RAM 是否同步”“物理灰阶残留是否仍在”。这是一条值得审查的差异，尚不能仅据此断言当前画面错误。

FreeInk 的 Metalio 路径单独管理初次绘制、灰阶残留、RAM 基准、每次请求的 `ContinuousReading` 上下文和 BUSY 完成结果。超时后不继续假设基准有效；清屏会有黑色过渡。当前板级序列与其 `FULL/FAST` 序列不同，不能机械替换几个常量。

来源：[SSD1677 实现](https://github.com/0x1abin/freeink-sdk/blob/094976e1d47ad7120cf461fec5f6b737eaabf13f/libs/display/FreeInkDisplay/src/driver/Ssd1677Driver.cpp)、[Metalio 适配说明](https://github.com/0x1abin/crossmux/blob/7dcd8b19031c9277376c7e0f8cacda4d7b5a43a1/docs/engineering/metalio-eink4.md)。

当前 `CONFIG_PAPER_GRAY_VERIFIED` 未开启。灰阶残留管理先以状态模型和主机测试覆盖；真实四灰阶不作为本轮图文阅读的前提，不悄悄打开未验收灰阶。

### 3.3 相邻页预备：先复用 CrossMux，再判断 M5 的剩余价值

CrossMux 的 `EpubReaderActivity` 已在页面完成、空闲超过400ms、章节未构建、内存条件满足时，扫描并预热下一页字形；本页也有预热扫描。`FontCacheManager` 的相关入口与该路径相连。这是实际调用关系，不只是一个未调用函数。

来源：[下一页空闲预热](https://github.com/0x1abin/crossmux/blob/7dcd8b19031c9277376c7e0f8cacda4d7b5a43a1/src/activities/reader/EpubReaderActivity.cpp#L611)、[字体预热管理](https://github.com/0x1abin/crossmux/blob/7dcd8b19031c9277376c7e0f8cacda4d7b5a43a1/lib/GfxRenderer/FontCacheManager.cpp)。

M5ReadPaper 的 `prefetchAround()` 补齐前后1页，条件允许时前后2页。其实现依赖自身 `BookHandle`、字体格式、全局状态；构建页缓存时还会临时跳转并恢复当前位置，字形接口使用 `uint16_t` 码点。我们的实现应保留32位 Unicode、无副作用预备和自己的资源租约，不能原样搬入。

来源：[M5 字体缓存](https://github.com/shinemoon/M5ReadPaper/blob/2380ca1d3ffd8ea530493a4225d8c9b6ed60c24b/src/text/font_buffer.cpp#L832)。

**决定：复用“预备下一页”的机制，并把它移到我们自己的空闲调度入口；暂不增加 M5 的第二套缓存。** 只有回翻/跨章节新字仍有明显等待且前后窗口实测有效时，再补窗口策略。

## 4. 接入结构：内容模块升级，系统外壳保持

```text
PAPER 中文首页 / 书库 / 阅读工具 / 设置 / 调试维护（保留）
                         │
             Reader 外观接口 + 任务/进度调度
                    ┌────┴────┐
       现有文本后端（TXT/回退）  CrossMux 图文后端（EPUB）
                                  │
                   解析 → 有样式块 → Section/Page
                                  │
         统一字体度量、SD资源、像素绘制、可取消后台任务
                                  │
            当前 Canvas / LVGL 入口 → 官方 SSD1677 驱动
```

以下接口名是拟定的实现边界，不代表仓库已经存在。

### 4.1 阅读后端接口与适配点

1. 在现有 `Reader` 外观后引入 `ReaderEngine`：打开、前后页、章节/锚点定位、查找、书签定位、页面进度、绘制及取消。UI调用继续留在 `Reader` 层。
2. `LocalDocument` 留作当前文本后端。CrossMux 使用 `Epub → Section → Page`，不要再次压平为 `Chapter.text`。
3. 把 `ui_pages.cpp` 直接依赖 `chapter().text.size()/offset` 的进度计算改为后端无关的 `ReadingProgress`；页数未完成时标注“估算”，不用占位数冒充总页数。
4. 阅读标题栏、按钮、菜单、中文文案与设计 token 保留。正文排版由新模块负责，系统界面字体不跟随书籍 CSS 改变。
5. 建议新增 `components/paper_reader_crossmux/`，区分固定上游源码、适配层和少量补丁；记录每个补丁的缘由、上游文件/提交和对应测试。

### 4.2 四个必须做完的适配面

| 适配面 | 具体做法 | 失败时的处理 |
| --- | --- | --- |
| 存储 | 将上游 `Storage/HalFile/Print` 操作收口到受限 SD 适配；书籍只读，缓存写独立命名空间；不引入第二次SD挂载 | 释放句柄和租约；坏缓存当未命中；原书与进度保留 |
| 字体与度量 | 用当前 PGF / `PackedFonts` 提供宽度、基线、字形和样式映射；常规/加粗映射当前已有字重；同一度量供排版与绘制 | 缺字、缺规格显式报错；不拉伸汉字补字号；斜体等缺少真实字形的表现要单独列入能力表 |
| 绘图 | 为上游依赖的 `GfxRenderer` 方法提取窄接口或维护可测试的适配补丁，输出到我们Canvas；图像逐行/分块写入 | 不让上游直接拥有面板、LVGL主屏或USB；绘制失败保留上一帧 |
| 平台/调度 | 适配计时、日志、内存分配、序列化、必要的XML/ZIP/图片库；工作任务有预算和取消点 | 无法限制内存/耗时的路径不进入默认配置；不整包引入Arduino应用启动流程 |

当前上游 `GfxRenderer` 是具体类，带 `HalDisplay` 和字体管理；解析器也引用 `src/fontIds.h`。这需要实际拆分依赖，不能当作替换一个虚函数即可完成。先列出被选源码的函数依赖清单，再裁剪边界。

上游使用 C++20、Arduino/PlatformIO，我们主体为 ESP-IDF + C++17。优先只给新组件设置必要标准并隔离兼容层；若产生额外硬件初始化、重复USB栈或整套全局设置依赖，停止该接入方式并缩小依赖，不全局照搬构建文件。尤其不引入上游平台配置中的保护检查包装/绕过参数。

现有 `ResourceGate` 的书籍修改互斥按 `owner == "reader"` 判断；旧备用适配器使用 `"crossmux-reader"`。新后端必须统一资源身份或改成显式“活动书籍”资源类型，并加测试，避免接入后漏掉“读书期间禁止改写该书”的保护。

### 4.3 进度、书签、字体设置的保护

- 旧定位包含 `book SHA + engine + chapter + UTF-8字节offset`；CrossMux有可见 Unicode 位置、锚点、页索引。**旧页码、字节偏移不得直接当成新引擎位置。**
- 新定位建议包含书籍内容SHA、引擎/格式版本、spine href、可见文字位置、锚点和上下文指纹。页码仅为当前排版结果。
- 首次切引擎保留旧记录，以锚点或上下文重定位；歧义时提示“原位置暂无法精确定位，可回到旧阅读器”，不静默跳到错误章节或覆盖旧书签。
- 新旧引擎分开保存进度记录，当前双槽CRC与原子发布沿用。回退读取自己的记录。
- EPUB默认后端只在验收通过后切换；TXT保持现状。避免在一次翻页中自动更换引擎。
- 选定字体、字号和页边距继续生效。书籍样式与用户设置的优先级固定：用户字号/字体优先，允许书籍提供对齐、缩进与强调；超范围样式有明确降级。

## 5. EPUB能力分阶段交付

### A1：保留现有阅读能力，建立新后端可用样本

先跑纯中文、中文夹英文和带目录锚点的 EPUB。沿用现有字体，完成打开/前后页/目录/书签/查找/重启恢复/字号变化。

主机对同一HTML进行文本顺序和标点边界断言；比对缺字、漏段、重复段。不能要求新旧排版逐像素相同，因为段落样式和断行算法会变化；系统外壳则继续做像素回归。

### A2：形成可见的内容收益

- 支持JPEG/PNG嵌入图片，先探测尺寸，再按页面需求解码；保持比例、限幅、透明PNG合成到白底。
- 首版采用确定性的黑白输出/抖动：图片能显示，无需提前开启真四灰阶。中间2bpp缓存不等于面板已能显示四灰阶。
- 保留已核实可映射的段落对齐、首行缩进、间距、加粗、标题块和横线。
- 宽图、图注、图片跨页、纯图片页、中文长标点段、超长英文串分别测。
- SVG、WebP、动画、OCR和浏览器级布局不列入首版承诺。上游有表格/ruby相关代码，待字体和页块适配后逐项启用；窄屏放不下时采用明确的阅读降级，不能丢正文。
- 损坏/超限图片显示可理解的占位与错误日志，允许继续读文字。上游图片渲染部分通过返回值/日志处理错误，适配层必须把失败转成我们的诊断状态，不能仅以“整页已刷出”标记图片成功。

### A3：缓存与首次可读时间

复用 Section 增量构建和页面缓存：只准备当前需要的页面，空闲时扩展；离开阅读、切书、USB接管、更新固件、开始录音时取消或暂停并释放资源。

注意 `buildSomeMore(N)` 按“产出页数”让出，遇到巨大段落或解压时仍可能长时间执行。须加时间/字节级取消点和独立工作任务，不能把 N=1 当成实时保证。

缓存统一归属 `/.paper/cache/reader/<engine-version>/<book-sha>/<render-key>/`。键包含：书籍内容摘要、引擎版本、字体文件摘要/字号/字重、视口、行距/边距、样式与图片策略。不要照搬上游仅按路径派生的书籍目录键作为内容完整性身份。

缓存是可再生数据：写临时文件、完成校验后发布；错误缓存按未命中处理。进度/书签仍在受保护记录区。不得启动时递归清空全部缓存，不得因目录改名误删原书。

**冷开书27.6秒单独验收。** 第一次解析含图片/CSS可能更重，不能默认新引擎一定更快。先计时定位；若主要耗时在PGF验证或字形读取，就在统一字体层优化，阅读引擎替换不能代替这项工作。首次显示进度提示和第一张可阅读页面分别记录时间，提示出现不算开书完成。

## 6. 刷新策略对照计划

### B1：先补可解释的显示状态

在当前驱动外增加小型状态策略，初版仍使用当前已运行波形：

- 面板状态：未知、有效黑白基准、存在物理灰阶残留、RAM已同步但残留未清、休眠、刷新中。
- 每次请求携带 Normal / ContinuousReading / ExplicitClean，避免“下一次快刷许可”跨页面泄漏。
- 仅BUSY完成成功后更新已呈现revision和基准。超时/复位/掉电/唤醒时失效；BUSY仍高时禁止后续RAM/休眠命令。
- 软件帧缓存存在与控制器基准有效分开表示；所有绘制入口、待机、关机、自检统一进入同一策略。
- 保留当前同图去重、GUI锁释放、输入队列和15次周期清屏，不重新实现这些已有能力。

### B2：测出收益后再试上游清屏方式

使用同一固件中的可切换实验策略，A组当前行为，B组状态管理变化。第一轮保持清屏频率、LUT、电压、SPI频率一致，以免多个变量混在一起。

若确认多余清屏来自状态处理，先修正判断。只有这些仍不足、且驱动状态测试通过，才单独评估 Metalio 黑脉冲清屏序列。它也会变黑，收益要看持续时间、恢复画质和残影，不能以“没调用FULL”代替视觉收益。

测试序列：文字前翻/回翻、阅读→菜单→阅读、黑底卡片→白底正文、图片→正文、手动清屏、睡眠/唤醒、BUSY超时注入后恢复；灰阶未启用时仅做相应主机状态测试，不冒称物理灰阶循环通过。

自动记录每个刷新原因、状态转移、RAM提交、BUSY耗时和完成状态。人工集中看一次对照：同光照同相机设置的白底/黑底细字、残影、1分钟/10分钟保持。帧哈希相同只证明像素一致，不能证明墨水屏物理画质一致。

## 7. 字形预备条件实验

先将CrossMux已有的“本页扫描/下一页空闲预热”接到我们的 `FontProvider` 和任务调度上；因为不迁入 `EpubReaderActivity`，这段调度需要明确迁移，不能假设复制 Section 就会自动运行。

出现以下证据才启用M5窗口策略实验：首遇字形读取占普通翻页总时长明显比例，或者反向/跨章节页面存在可重复的卡顿，现有下一页预热未覆盖。

实现限制：

- 初始只预备 +1 页；先利用现有256KiB字形缓存，不新增平行缓存。反向场景有收益再考虑 -1 页，暂不默认±2页。
- 预备请求按书籍/字体/排版/SD代际绑定，可取消；32位码点，包含字重/规格，不改变阅读位置、不写用户进度。
- 用户翻页/菜单/USB/录音任务优先；按时间及字节分片。不得为预备整页而长时间持有当前 `PackedFonts` 互斥锁。
- 如需合并SD读取，只在有界作业内保留文件句柄；切资源、失败或取消即关闭。USB安全交接不能被常驻字体句柄阻止。
- 检查预备是否逐出了本页/UI字形；收益要扣除额外读卡、耗电、内存占用和被用户打断的无用工作。

若CrossMux现有预热已经达标，M5候选以 **SKIP：功能重叠、无新增收益** 结案。这也是成功筛选结果。

## 8. 收益准入与测试方法

以下是拟定工程门槛，**尚未实测达成**。基线和候选使用同一设备、SD、字体、测试书、屏幕尺寸、供电与刷新周期。

| 项目 | 最小验收门槛 |
| --- | --- |
| 内容收益 | 原有图片占位用例变为正确可见插图；选定段落/强调用例通过；中文顺序无丢失/重复，书签定位正确 |
| 普通文字翻页 | 至少30个连续不同页面+10次回翻，p50/p95相对重测基线均不恶化超过10%；超过则保留旧后端默认 |
| 冷开/重开 | 分别测5轮重启后、冷缓存首开、磁盘缓存命中、同会话重开；记录第一张可读页面，不能只报最快一次 |
| 宣称“冷开提速” | 相应标准样本至少降低30%才标明显收益；未达标只认内容收益并保留冷开缺口，不用微小改善结案 |
| 预备实验 | 新字多的翻页p95至少减少150ms且软件准备段减少20%以上；无暖页/菜单/USB明显回退；否则关闭实验 |
| 刷新实验 | 同一动作轨迹的非必要清屏确实减少，或过渡耗时改善≥20%，同时残影/细字/保持画质不劣于A组；缺物理观察则NOT_PROVEN |
| 安全/恢复 | 无新复位、死锁、读卡互斥失效；书籍及旧进度哈希/记录保留；两应用槽结构、eFuse规则不变 |

### 8.1 计时点先补齐

从输入到可读画面分解：入队等待、书籍SHA、ZIP索引/解压、HTML/CSS解析、字体SHA/PGF校验/索引加载、排版、字形读卡、图片探测/解码、软件绘制、SPI提交、BUSY、位置保存。

同时记录命中/未命中、SD读取字节/打开次数、内部堆最小值和最大连续块、PSRAM峰值、任务栈低水位、取消耗时。`queued`不算完成，提交成功不算BUSY完成，软件截图不算物理屏幕验收。

现有 `paper.status`、`host/paper_performance_acceptance.py`、`host/paper_runtime_smoke.py` 延伸使用；不另建一套设备控制服务。诊断字段增加请求/作业ID，避免旧请求或旧图像误配测试。

### 8.2 测试语料和错误场景

使用自生成、公开许可或用户已有书籍在本机测试，不上传私人电子书。至少覆盖：

1. 纯中文小说、中文/英文/数字混排、禁则标点和长英文词。
2. 标题/段落/列表/引用/强调、目录锚点与脚注；小表格/ruby为独立能力项目。
3. JPEG、带透明度PNG、宽图、纯图页、图文交替及损坏图片。
4. 大章节、跨章节前后翻页、修改字号后定位、重启恢复。
5. ZIP路径穿越、超大解压声明、截断缓存、SD满/缺卡、资源被替换、USB接管、任务取消。

图片与XML/ZIP使用大小、维度、元素数量和解压总量上限；禁网络资源请求与外部实体。新解析器遇异常应失败可恢复，不能带坏其他系统功能。

### 8.3 资源与授权门槛

- 新功能以现有5MiB应用槽为硬限制；建议首轮镜像目标≤4MiB，至少留1MiB给后续功能。空间不足先裁不相关依赖，不复用备用OTA槽。
- 建议首轮内存门槛：最坏用例内部空闲≥40KiB、最大块满足所需最大内部申请且建议≥16KiB；PSRAM至少保留2MiB。先测基线峰值再固定门槛，不能用单次快照判断稳定。
- 图片用行/条带解码，48,000字节1bpp或96,000字节2bpp目标图可分块；禁止无预算解码整张巨大RGB图。SD派生缓存建议首轮总额256MiB、单书64MiB，空间不足降级为无缓存；数字为拟定上限，可按实测下调。
- 固定源码、依赖、字体和构建配置；MIT/Apache-2.0等许可证文件与修改记录随使用范围保留，实际引入的解码器等另核许可证。原字体授权沿用。
- 任何设备写入沿用现有清单、校验、备用槽、回退流程；当前计划不授权修改eFuse、绕过安全保护或改分区。

## 10. 明确停止或缩小吸收范围的条件

- 新引擎能出图，但文本顺序、书签或用户字号丢失：不切默认。
- 暖翻页退步超过门槛：先找接口/缓存问题，不能用“功能更多”掩盖退步。
- 内部RAM或镜像超预算：裁剪不相关功能；仍不满足则保留为研究分支，不挤占恢复槽。
- 预热被已有能力覆盖、或只是搬移等待且用户总体验没收益：跳过。
- 刷新只降低日志里的FULL次数，照片残影更重：拒绝该策略。
- 无法维持USB接管、取消、应用回退、原始书籍和进度保护：优先修边界，功能接入暂停。

**完成定义：每个被保留的模块都能回答“补了哪个缺口、测出了多少收益、占用了多少资源、失败怎样回退”。** 余项允许明确SKIP或NOT_PROVEN，不以“吸收了很多开源代码”作为成功标准。
