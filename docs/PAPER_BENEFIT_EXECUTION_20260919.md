## 已实现，主机检查通过

### 字形短期批量读取与分段计时

- `FontReadBatch` 为一次文字/正文绘制保留一个字库文件句柄，支持嵌套；切换字库、资源失效、失败或退出最外层作用域时关闭。
- 沿用 PGF 头、索引、几何、CRC、SHA 检查，没有降低校验。仍使用现有字形LRU，没有添加第二套缓存。
- 绘制作用域持有SD租约，USB接管必须等其释放；文件不会在后台长期占用。
- `paper.command` 增加实验动作 `font-io-mode`，值为 `legacy` / `batch`。切换清空字体缓存；选择不持久化。候选编译默认 batch，是否作为稳定默认仍需真机比较。
- `paper.status.app.font_cache` 增加累计 `hash_us / validation_us / index_us / glyph_io_us / glyph_opens / batch_io`。用前后差值解读，不能把累计计时当成单次延迟。
- 原生无字形缓存测试：8个不同汉字，legacy打开8次、batch打开1次；两者像素完全一致；嵌套、缺字失败、USB互斥/释放通过。

### perf4 ABBA 结果

证据：`artifacts/paper-perf4-20260919/font-abba.jsonl`。同一固件、同一本书、相同起点，legacy/batch/batch/legacy，每组前翻10次、回翻10次；每组均核验返回原位置。合计80次翻页，boot ID 未变化，回执和字体检查通过。结束恢复 batch 并回到首页。

| 指标 | legacy | batch |
|---|---:|---:|
| 前翻20次中位 | 1.8185秒 | 1.6965秒 |
| 前翻 P95 | 1.926秒 | 2.767秒 |
| 回翻20次中位 | 1.697秒 | 1.695秒 |

| 前翻累计字形文件打开次数 | 910 | 22 |

解释：batch 对字形 I/O 有明确收益，前翻总延迟中位约减少6.7%；显示耗时基本相同，回翻中位基本相同，冷开未解决。P95未一致改善，不能宣称全面更快。保留 batch 作为当前候选，仍需更多不同页面和刷新周期对照，未冻结稳定版。不能把本轮10个位置的重复测量称为30个不同页面验收。
