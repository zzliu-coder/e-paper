# 字体试验台：原轮廓与灰阶实验

**第一、第二阶段的代码已经接进同一个试验台。电脑端检查通过；真机光学验收仍待完成，第三阶段尚未实施。**

直接打开 `字体试验台-直接打开.html` 就能试用。它包含已生成的固定文字样张，不带字体文件，不访问网络或USB。需要读取更多字体或控制真机时，双击 `启动试验台.command`；第一次会在包内创建Python虚拟环境并安装依赖，需要网络。

## 最快的四个入口

| 网页按钮 | 用来判断什么 |
|---|---|
| ① 与原轮廓比较 | 左边关闭微调，右边切换算法，判断优化带来什么变化 |
| ② 与固件原样比较 | 直接用原 UI 字库作为基准，检查是否优于现状 |
| ③ 同字黑白／灰阶 | 每行同一份字形，左右只改变显示输出 |
| ④ 灰阶色块预览 | 四个实心色块；真机需要单独启用灰阶 |

字体、字号、算法、墨色、字重、文案和底色均使用直接按钮。可以自由选矩阵行列，固定A并调整B；16—40px全部整数尺寸可选。无效墨色在网页禁用；设备按钮划线并忽略点击。旧Lab3/4打开入口继续导向统一面板，评分文件保持原样。

## 字体与基准的实际范围

当前 SD 资源包已预生成 8 个字体家族的真实可用字重、六种轮廓处理、25 个字号，合计 12000 张 A8 固定样文图片；清单里的每个字体入口都有至少一个可用字重，样本生成失败数为 0。黑白／四灰阶和正反色从同一批数据转换，避免重复存储。

八个黑体来源入口保留：思源、MiSans、鸿蒙、新晰黑屏幕版、文泉驿、苹方SC、黑体SC、Noto同源对照。当前包已载入这些入口的真实样本；某字体没有某个真实字重时，界面只提供它实际存在的字重，设备端也会解析到该字体最近的真实字重，不用另一字体顶替。思源与Noto是同源对照。

「固件原样」明确指**原 UI 思源 Medium 字库**。它直接用18、20、22、25、28、30px六档原字库；真实阅读器的 MiSans 路径仍是另一条链路。普通字体试验样本和固件原样基准不能混为同一个来源。

## 合入设备源码

先保留原固件备份，在独立工作副本里操作。本工具默认检查、不写入。不会自动编译、刷机、改分区或推送GitHub。

```sh
python3 integrate.py --repo /你的/e-paper
# 输出 validated 后，才执行写入：
python3 integrate.py --repo /你的/e-paper --apply
```

已有 `.fontbench-install.json` 的上一版统一试验台可以原位升级，前提是被管理的文件未发生本地修改。Lab3固定提交和前次Lab4也可合入。目标已变化时会停止；不要删除校验、不要硬覆盖。详见 `docs/合入说明.md`。

复制包内 `sdcard/inkdesk/fontbench` 到SD对应位置，替换旧同名试验资源；先备份旧目录。**评分JSONL在外层，不属于这个资源目录，保留它。** 网页读取更多真实字体后，可点「生成真机SD资源」生成新的同版本样本。

用已有ESP-IDF环境编译工作副本，按项目已经验证的app-only流程上机。这个包不含完整仓库、工具链或可刷写bin；完整ESP-IDF链接与Flash分区余量本次未验证。

## 真机灰阶

同板实验已实现：四实心色块、同字黑白／灰阶、灰阶目标帧读回、受控快刷、错误停止和退出恢复。每次开机默认关闭。

进入统一面板，确认GDEM0397T81／SSD1677，按「启用灰阶」→「色块」。普通页面使用原字体与原显示路径；离开实验前自动执行状态恢复保护。首次上机请按 `docs/灰阶真机验收.md` 做人工观察和自动验收。

**当前没有哪一项评分被认定为真机最佳。** 软件目标像素正确、驱动命令成功、肉眼看到更舒服，分别记录。真机验收结束后才做第三阶段。

## 包里重点文件

`web/` 是网页源码；`app/` 是本机生成与控制；`overlay/` 是设备组件；`changed-source/` 是已合成的完整主应用文件；`integrate.py` 将它们接到已核验的原项目。`tests/` 与 `evidence/` 保存本次真实检查过程，`docs/` 有算法解释、合入方法与真机验收。

无字体文件、无烧录动作、无GitHub写入。Nothing设计系统、原阅读器字体、笔记与待办存档都保持原样。
