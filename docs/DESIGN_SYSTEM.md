## 1. 已决定的方向

- 用户在实机上选择黑体作为主要方向；当前活动候选为思源黑体、霞鹜新晰黑屏幕版和文泉驿微米黑。文楷保留为历史回滚输入，不作为当前方案。
- 风格指纹：精密的纸面仪表、克制的黑色主面板、清晰中文、模块化比例、少量点阵和印刷式纹理。
- 保留既有底座、原生控件与 USB 调试能力。未来页面应调用统一公共组件。
- 重要信息首先保证中文可读性；灰色、点阵、虚线都有明确角色。

## 3. 已核实的代码事实

- 逻辑画布 480×800：`main/inkdesk_r2/core/types.h`；面板 800×480，适配器做 ROTATE_270。当前文字没有整页缩放。
- 板级配置注明 3.97 英寸：`main/boards/metalio-e-ink-4/config.h`。据此计算 `sqrt(480²+800²)/3.97 ≈ 235 PPI`，此为标称尺寸推算。
- 字形从原始 OTF/TTF 直接生成 18/25/28/30px：`host/build_ui_fonts.py:20`。字形保存 2-bit alpha（0/85/170/255），表示覆盖率，不等同于屏幕输出 4 灰阶。
- 输出为 I1 单色：`sdkconfig` 的 `CONFIG_LV_COLOR_DEPTH=1`；`main/display/lv_adapter_display.cc:1268` 注册单色显示。
- 圆角全部硬编码 8px、轮廓 1px：`main/inkdesk_app.cc:148`。半径约 0.86mm，小半径在单色像素网格上的阶梯容易被看见。
- `Draw.black` 只有布尔黑白选择。`ui_demo.cc` 已有 text/panel/button/bar 等内部辅助函数，仍缺公共的语义 token、共享状态规范和页面模板。

### 3.1 找到的黑白不对称缺陷

本地 LVGL 包标记 9.5.0，软件渲染、ASM=0；编译文件清单包含 I1 blend 与 letter 路径。
文字 A2 覆盖率解包为 A8 mask 后进入该混合分支：

`managed_components/lvgl__lvgl/src/draw/sw/blend/lv_draw_sw_blend_to_i1.c:294`

```c
new_bit = (mask_val * src_color + (255 - mask_val) * current_bit) / 255;
```

src/current 是 0 或 1，整数除法截断。结果：

| 字形覆盖率 | 白底画黑字 | 黑底画白字 |
| --- | --- | --- |
| 0 | 保留白底 | 保留黑底 |
| 85 / 170 | 已变黑 | 仍为黑，白色边缘消失 |
| 255 | 黑 | 白 |

因此同一字形黑色笔画包含全部非零覆盖率，白色笔画只包含全覆盖像素。圆角抗锯齿的 mask 混合也可能受到此规则影响，具体边界需渲染测试。

只读计算复现：用当前思源字库文字“阅读进度已加入书签”，18px 时黑色笔画像素 1364，白色笔画像素 622；25px 时为 2396 / 1534。此为字形与公式计算，非光学测量或完整 LVGL 实机复现。

判断：这是已证实的渲染逻辑不对称，且与实拍现象一致；尚未通过修复前后设备对照确认其贡献比例。换字体、增加字体 bpp、只加粗白字，都不会自动消除此公式问题。

外部核对：Context7 查到 I1 单色说明与字体 alpha 格式，但未直接解释该缺陷；继而核对 [LVGL v9.5.0 官方源码](https://github.com/lvgl/lvgl/blob/v9.5.0/src/draw/sw/blend/lv_draw_sw_blend_to_i1.c)，相同混合逻辑存在。暂不推断其它版本是否修复。

### 3.2 修复路线（尚未实施）

1. 先给当前 I1 混合路径做带阈值的对称黑白量化对照，覆盖 mask/opa/组合透明度分支。用可追踪补丁和锁定版本维护，不手改供应商文件后遗忘。
2. 测同一字形黑白互换是否保持轮廓；所有 mask 0..255、非字节对齐 x、stride、裁剪和圆角四象限都纳入主机测试。
3. 将经过修复的渲染结果与另一条“离线按目标字号生成清晰 1-bit 字形”候选比较。必要时再比较中间灰度画布统一量化；不立即扩大显示管线。
4. 再校准字号、字重、半径、线宽。恢复正常笔重后，Medium 是否仍适合正文需重新看实机。
5. 仍有黑底发灰或残影时，再比较相同内容全刷/局刷结果，不直接更换面板波形。

## 4. 灰色策略

当前默认能力为单色，不承诺真实灰阶。

- **真实灰阶**：一个像素显示中间亮度。需要本机面板、控制器、驱动、LUT/波形及刷新策略一起验证；更改一个颜色值不能保证得到它。暂不启用未核实灰阶波形。
- **网点灰**：以黑白点的空间密度形成视觉灰色，当前 1-bit 路径可承载。纹理可见，视觉效果与均匀灰色不同；先比较 25%/50%/75% 覆盖率的静态小块。
- `surface.subtle`、`ink.secondary` 保存语义角色，当前可映射为留白/轮廓/明确文字；灰阶验收通过后替换映射，页面业务无需知道面板灰阶实现。
- 正文、关键按钮标题不做网点；纹理优先用于大块装饰、非关键状态底纹或图案。
- 不依赖灰色单独区分“禁用/选中/可点击”，同时提供勾选、边框或明确标签。
- 避免大面积密点背景和持续动画；装饰纹理随页面更新，不单独定时刷新。

## 5. 风格指纹和设计 token

以下数值为校准候选，禁止标记“实机通过”后直接全局推广。

| 维度 | 规则 / 候选 |
| --- | --- |
| 中文字体 | 思源黑体作为主 UI；正文与标题分角色。文楷可选，不作为主仪表字体 |
| 数字 | 时钟/少量关键指标使用点阵；书页、百分比、正文数字优先清晰常规数字 |
| 文字角色 | caption / body / title / display；caption 对比 18/20/22px，body 对比 25/28/30px；未生成的字号必须从字体源重建 |
| 间距 | 以 4px 为基础；先保留当前外边距20px、卡间距12px、卡内边距16px，再做视觉校准 |
| 圆角 | 比较 radius=0/8/12/16px，修复抗锯齿后再选择；不直接以“越大越光滑”作为结论 |
| 线宽 | 1/2px 对照，配合像素对齐；不要把所有边框一起加粗 |
| 虚线 | 候选 dash=4或6px、gap=4px、线宽1/2px；用于分隔/辅助框，圆角闭合处统一处理 |
| 黑色面板 | 通常每页一个主要视觉锚点；反白用于大数字或较大标题，小号说明优先移到白底 |
| 灰色角色 | 黑/白为已支持；浅/中灰为待验收映射，禁止任意散落数值 |
| 图标 | 固定尺寸、统一线宽；图标和点阵各有用途，不将所有图标像素化 |
| 状态 | 普通、选中、禁用、忙碌、失败、断连；视觉状态必须与设备实际结果一致 |

中文排版还须统一实际字形 advance、基线、行距、段距、标点禁则和截断方式。当前样机正文以近似字符宽度分行，不能作为最终电子书排版器。

## 6. 设计系统在固件里的位置

`应用页面 → 公共组件 → tokens + 排版/刷新规则 → LVGL 渲染适配 → 墨水屏`

- **Design System / 设计系统**：以上整套规则、代码、示例和验收依据。
- **Design Tokens / 设计变量**：字体角色、间距、半径、颜色角色等统一参数。
- **Component Library / 组件库**：真正可复用的原生按钮、卡片、列表等代码及状态行为。
- **Patterns / 页面模式**：阅读页、设置页、首页如何组织组件与交互。
- **Component Gallery / 组件展示与测试页**：在设备上集中展示各组件、状态和测试参数；承担嵌入式环境中的组件工作台角色。

拟提取至 `main/ui/`（此目录结构是计划，尚未创建）：

```text
tokens / typography / primitives / components / patterns / gallery
```

现有 `ui_demo.cc` 为迁移样本，不能把它的硬编码坐标直接冻结成完整设计系统。

### 首批公共组件契约

| 组件 | 输入和状态 | 关键验收 |
| --- | --- | --- |
| PageHeader / StatusBar | 标题、返回、真实电量/网络状态 | 长标题、断连、未知值、触摸与实体键 |
| Panel / Card | 普通、强调、轻背景、可选虚线 | 四角一致、边框不缺口、内部留白 |
| Button / IconButton | 普通/选中/禁用/忙碌 | 反白清晰、刷新中不重复执行、触控范围独立于字宽 |
| ListRow / SettingRow | 标签、值、说明、动作 | 长中文、无值/未知值、开关状态不提前假成功 |
| Progress / Meter | 实际值、上下限、未知状态 | 黑白对照、未加载和 0% 区分、静态显示 |
| ReaderTypography | 正文、字距/行距、标点、阅读位置 | 字形完整、工具显隐不丢文、不改变当前位置 |
| Empty / Error / Busy | 原因、恢复动作 | 清楚说明下一步、长任务仍可退出 |

页面只提供内容、状态和动作，不自行决定任意半径、颜色或发起屏幕刷新。公共渲染/刷新层合并更新，维护输入时序。

## 7. 下一轮实施与验收顺序

1. 渲染校准页：同一段中文黑白互换，1/2px边框、四种圆角、虚线、网点密度并列；使用实际字体和渲染路径。
2. 主机自动验证：mask 黑白对称、边界/裁剪、中文覆盖、组件全部状态、无额外空闲刷新。
3. 受控应用更新后读回实际帧，确认修复结果落到设备；真实灰阶能力保持单独验证状态。
4. 用户集中看一次校准页，确认小字可读、反白不缺笔画、圆角和网点舒适。若全刷/局刷差异明显，再补刷新对照。
5. 冻结通过的 tokens，提取公共组件；先迁移首页和阅读控件，再供新功能使用。

完成标准：以后修一个 Button 或字体策略，所有引用它的页面一致改变；新页面不得复制私有按钮画法。代码测试、帧缓冲检查、物理观感三类证据分别保留。

本轮交付为本草案与四份原始用户截图；渲染补丁、原生公共组件库和校准页尚未完成。
