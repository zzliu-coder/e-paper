# 黑白驱动下的字体替代方案

## 边界

grayab1真灰阶已由用户照片否决：噪点、反白、旧页面残留。根因未证实。monoab2编译关闭两个灰阶开关、拒绝gray4命令，不改面板电压或波形；全部使用已有黑白显示路径。网点是黑白空间混合，不能称为真正的灰阶抗锯齿。

## 方案与入口

系统设置 → 开发与维护 → 字体清晰度对照。

- 原始黑白：同一MiSans覆盖率字形，二值阈值。
- 笔画微调：仅对两侧均为实笔画的弱覆盖单像素间隙补点；反白对称处理，避免全字膨胀。
- 网点模拟：固定2×2有序网点，纯黑白保持不变，中间覆盖率转为25%/75%白点。可能增加颗粒感，默认不启用。

“字号与色块”依次显示18/22/26/32px和色块页。每页相同文字、分别白底黑字及黑底白字，同页切换方案比较。四种字号分开，减少字库索引反复读取。

## 验收

原生检查15个页面组合全部仅含0/3像素、灰阶命令禁用、阅读设置不变、反白补点正确、网点覆盖比例正确。样本文字微调每页改变50–86像素，网点734–1060像素；有差异不等于更清晰。原生和ASan通过，Python217项通过。

真机用`host/paper_mono_compare.py --out <新路径>`记录15种组合的身份、模式、回执、耗时，不允许将显示回执当作物理质量证明。实机结果另行追加。保留原始黑白默认，等待用户视觉选择。

## 用户视觉反馈

用户提供18px原始黑白照片并确认：笔画微调与原始黑白肉眼无明显区别；网点模拟有改善，两种方案均仍有局部发暗。用户随后明确纠正：**字号越小，发暗与不清晰的问题越明显**，不能写成小字改善更明显。最新补充为：网点模拟整体好很多；色块测试中原始黑白/笔画微调仅左两黑右两白，网点能分出四档。故笔画微调暂无明显收益，网点为有用户观察支持的候选，尚不变更系统默认。照片中的局部暗区尚不能区分刷新残影、画面数据或反光。

色块行为符合当前代码：阈值输出把0/1归黑、2/3归白；弱笔画补偿不会改变均匀色块；2×2网点以0/25/75/100%的白点比例模拟四档。四档可分只能证明灰调有区分度，不能单独证明小字笔画、残影或真灰阶已合格。

## 下一轮取舍与验收门槛

保留原始黑白基准，优先优化已有视觉收益的网点方案；笔画微调仅保留实验记录。真灰阶另作受控对照，不因名字或灰阶数量直接设为默认。

1. 真灰阶先查清数据传输、两个显存位面、初始化与刷新基准差异，禁止无依据调电压或套用其他面板参数。
2. 真灰阶依次验纯白/纯黑/四灰阶平面，以及灰阶回黑白清屏；没有噪点、反白、旧页残留才进文字测试。物理失败立即结束该候选，不拿错误画面与网点排名。
3. 用相同字体、相同字符、同字号18/22/26/32px、正反色比较。算法、字重、字号、刷新策略一次只变一项。
4. 将“全清后质量”和“连续快翻质量”分开。记录暗区、细笔画缺失、颗粒、残影、人眼黑闪、显示阶段耗时与字库准备耗时；用户只参与屏幕物理观感。
5. 默认选择允许按场景区分：普通菜单/正文优先速度与清晰度；图像/封面可选择质量模式。任何新增默认都等同页实测及用户确认后再改。
